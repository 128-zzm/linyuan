# CRTC 抢球小车 学到的知识总结

**参赛队伍**：CRTC 抢球小车队　　**整理**：谷宸溪（队长）、邓雅诗（电控）、徐一鸣（机械）

本车研制过程中学到并验证过的知识，按机械 / 电控 / 硬件三部分记录，供赛前复习和后续复用。

---

# 一、机械

**选型先列硬约束再找方案**
选 MeArm 型不是因为它先进，而是它每条特点都落在本车限制上：4 只舵机对应 4 个自由度、舵机全下置（SG90 力矩小）、板件结构适合 FDM 打印、四连杆让夹爪姿态自动保持。先喜欢上某个结构再想办法适配，基本都会返工。

**平行四边形连杆末端姿态自动保持，但角度耦合**
大臂与小臂构成平行四边形对边时，夹爪姿态在整个行程内恒定，夹着球抬臂不会翻掉。代价是两个关节角度互相耦合，不能"一个舵机管一个角度"。抢球这类任务不用解四连杆方程，几组预置动作位（低位待命 / 抓取 / 抬起 / 释放）就够，代码里就是几张角度表。

**舵机下置能大幅降低负载**
负载力矩 = 末端重量 × 力臂。舵机装在臂上等于让它自己抬自己。动力全放底座附近、经连杆传上去，小力矩舵机也能带动整臂。

**建模先画骨架草图再建零件**
关键尺寸（臂长、关节间距、回转半径）放进用户参数表，改一个数全模型联动。后期改尺寸不用推倒重建。

**装配仿真不能省**
干涉在电脑里改是零成本，打印出来才发现要重打一堆件。建 Joint 并设真实行程后，逐项查：极限位置是否干涉、行程够不够、夹爪能否达到所需高度和距离、四连杆是否全程保持姿态。

**3D 打印零件的工艺要点**
板件按受力方向加筋；外露尖角做圆角减少翘曲；打印孔通常偏小，装配孔和销孔要放余量；塑料件用自攻螺钉省事；大件拆成若干件时接口加定位销；FDM 件层间结合最弱，受力方向避开 Z 向拉伸。

**开源模型不能直接打印**
舵机型号、板材厚度、加工精度都不同。下载后先拆结构原理，再按自己实物重新建模；舵机安装座这类配合件先单独打样验证。

**麦轮排布决定能不能横移**
只有对角平行（俯视左前 ∥ 右后、右前 ∥ 左后）能横移。左右镜像会打转、前后镜像不动，这两种物理上凑不出"纯平移 + 零力矩"，改代码没用。症状：打转 = 左右镜像，完全不动 = 前后镜像，能横移但方向反 = 排布对了改一次符号。注意前后和原地转在任何排布下都正常，所以能前进不能证明排布对；同侧互换（左前↔左后）无效，同手性换了等于没换。

**SG90 使用常识**
塑料齿，装舵盘前别用手硬掰输出轴；装舵盘前先让舵机回中 90°，行程才左右对称；通电保持时的高频声是正常现象，判断堵转看外壳是否发烫、端点是否卡顿。

**形状没定时用硬纸板做原型**
尺寸还要反复调的时候，纸板改一刀只要几秒，打印件要等几小时。等周边件到货、布局确定后再做正式版本。

# 二、电控

**APB1 定时器时钟会 ×2**
APB1 是 36MHz，但其上的定时器时钟自动 ×2，实际 72MHz。算出的 PWM 频率与实际不符时先查这里。

**不同频率的 PWM 不能共用定时器**
同一 TIM 的通道共享 ARR，频率被锁死。本车电机 10kHz 走 TIM2、舵机 50Hz 走 TIM3（PSC=71 / ARR=19999，1 tick = 1µs，脉宽换算直观）。

**用结构体数组代替硬编码引脚**
每个电机的通道号和方向脚存进一张表，换接线只改表，业务逻辑不动。测试中多次改通道、改方向，都只动了表里几行。

**-O2 会删掉空循环延时**
现象是 Debug 能跑、Release 就坏。GCC 在 -O2 下把空 `for` 循环体直接删掉，靠指令周期实现的时序全失效。改用 DWT 延时（读 `DWT->CYCCNT`，72 ticks/µs）。凡是依赖指令周期的时序都不能用空循环。

**PS2 不锁模拟模式，小车会自己跑掉**
上电默认数字模式，摇杆字节返回 0xFF/0x00，被当成推到底。改为上电发配置序列锁模拟模式，并用应答 ID（0x73/0x79）校验握手。

**摇杆映射与死区**
摇杆值减中值 128 后 ×8 映射到 ±1000。死区用于消除中位抖动，本车从 12 调到 6~8；死区和车速上限这类参数理论值只能参考，最终靠实车手感定。

**映射假设必须实测验证（本项目最大的教训）**
横移调了五轮符号都不对，最后写体检固件才发现电机通道与轮位映射从第一天就写反了（一直按 M0=左前 假设写，实际 M0=左后 / M1=左前 / M2=右后 / M3=右前），五代代码全在错误地基上。一个 12 秒的体检固件顶五轮盲调。

**符号只有两种组合，试完还错就查机械**
两种都试过还不对，说明问题不在代码里。我们当时继续改代码白绕三轮，后来做力合成枚举才发现是轮组排布问题。配套认知：队里说"每次都这样"时通常指出了一个真不变量——问题不在被反复更换的变量上，而在从没动过的变量上。

**"车不动"不等于"电机没响应"**
几个力互相抵消时同样表现为不动，原地打转看起来也像没动。排查先看"该转的有没有转"（漏写驱动这类真故障），再看"转的方向对不对"（只是系数问题）。

**代码审查要盯逻辑完整性**
main.c 里只有 3 个 `Motor_Set`，M2 没写、M3 被孤立绑到别的变量，单电机测试只看 M0 一直没发现。要做结构化核对：逐个列出 4 个电机是否都有控制。

**诊断固件留成编译开关**
`MIN_MOTOR_TEST`、`MOTOR_DIAG`、`SERVO_DIAG` 常驻工程，测试代码不删。体检动作有时间预算：每段时长要 ≥ 行程 ÷ 速度，否则目标走不到。踩过一次——槽位 4 秒、速度 20°/s，90°→60° 需 1.5 秒却只给 1.2 秒，实际只摆 24°，表现为"幅度太小"查不出原因。

**新功能用开关隔离**
多个控制目标叠进同一组公式，一个出问题会污染全部功能。默认态 = 已验证功能，实验态 = 待调试功能。调横移全程前后功能一次没坏。

**安全逻辑必须实车测**
手柄重连后电机不转，原因是掉线时拉低了 STBY 而重连分支没恢复。掉线急停（PWM 归零 + 方向拉低 + STBY 断电 + 舵机回中）要真关手柄电源反复测；舵机示教值也要在掉线分支同步回中，避免重连跳变。

**舵机脉宽与角度**
SG90 标称 0.5~2.5ms 对应 0~180°，但廉价舵机常在 2.0~2.2ms 就到机械限位。本车把 CCR 上限收到 2400µs（≈171°），上层用 0~170° 夹紧。上限做成宏，装到机构上发现顶死改一个数字即可。

**摇杆给驱动，按键给机构**
两个摇杆 4 个轴全被底盘占用时，机构走按键更清晰：← → 控回转，↑ ↓ 与 L1/L2 控两个根部关节，R1/R2 控夹爪，△ 全部回中。按住连续转、松开即停，角度边界夹紧。

**先给示教器，再固化动作**
机构关节分工没确定前写死动作序列只能是瞎猜。先做手动示教，操作员摆出姿势读出角度，再固化成一键动作位。

# 三、硬件

**电池极性必须用万用表确认**
电机不转时我直接动了电池线，正负极接反，TB6612 当场爆掉（驱动板坏了，主控和固件没事）。颜色、线序、感觉都不可靠。另外"不转"第一步是看 LED，LED 不亮说明程序没跑，跟接线无关，此时不该动电源。事故本质是违反了"一次只改一个变量"。

**供电分两路，且必须共地**
电机大电流直取电池，主控与舵机经降压取 5V。电池负极、降压 IN−、主控 GND、驱动板 GND、舵机地线、手柄 GND 全部并联，少接一处就会乱抖或不听话。

**舵机不能从主控板的 5V 针取电**
那个针是给板子供电的输入口，走细铜箔，几只舵机同时启动的冲击足以把电压拉垮，表现是舵机一动主控就重启。舵机电源统一走降压模块，并在 5V 与地之间并 470~1000µF 电解电容（长脚接 5V）。

**分段上电**
验极性 → 只接电源上电摸温度 30 秒 → 接信号线 → 接电机 → 上电看结果。全车联调按"电源 → 主控 + 手柄 → 电机 → 舵机"四段逐段验证，出问题立刻定位层级。

**TB6612 三个必接项**
STBY 必须拉高（悬空时输出级禁用，电机永远不转，手册默认你接了不提醒）；VM 接电池、VCC 接 3.3V 逻辑电、GND 两处都接；单通道持续 1.2A，按马达堵转电流核对。本车 STBY 用释放出来的 PA15，急停时做 PWM 归零 + 方向拉低 + STBY 断电三重动作。

**驱动电压要匹配**
电池满电 8.4V 直驱标称 3~6V 的 TT 马达会过速过流。在驱动层加软件限速（本车 70%），对外接口仍是 ±1000，调最高速只改一个数字。

**锂电池要加保护板**
18650 裸电芯必须配 2S 保护板，否则过放会永久损伤电芯。本车目前仍是裸电芯，待补。

**电压跌落是最隐蔽的故障源**
试车时"偶发掉线""舵机抽动"看着像程序问题，实际是电池低于约 7.2V 时降压模块掉出稳压区、5V 跌落导致主控复位。试车前先量电压；后续可加 ADC 欠压报警，注意 F103 的 ADC 时钟上限 14MHz，分频要从 /2 改 /6。

**STM32 引脚的隐藏约束**
PB2 是 BOOT1，Blue Pill 上没引到侧排针，接线前先确认板上真有这个脚；PB3 / PB4 / PA15 默认归 JTAG，要在 `HAL_MspInit` 里开 `SWJ_NOJTAG` 才能当普通 IO；48 脚封装资源刚好够用没有冗余，定时器分配要先规划。

**模块丝印不统一是常态**
PS2 接收器丝印是 DI / DO / CS / CLK，不是常见的 DAT / CMD / ATT。拿到模块先查文档，记法是"以主控为主体：DI = Data In，DO = Data Out"。还要注意接插件位置，有些排针是模块与转接板之间的出厂连接头，拔掉就断链。

**硬件先于代码验证**
点灯（工具链通）→ 单电机（驱动通）→ 全车（系统通）。跳过任何一步，后面的现象都会变成"不知道哪一层坏了"。

**文档里的映射表要跟着实测回改**
过时的映射表比没有表更危险。接线总表里电机位置一直写着体检前的旧值，破案后才发现。每次拿到新的实测真值，都要回头同步所有文档。

## 附：跨领域的三条方法

1. **一次只改一个变量** —— 违反这条，诊断和维修就会搅在一起（爆板事故的直接原因）。
2. **盲调超过三轮就换方法** —— 写诊断工具拿地面真值，别继续改参数。教训写出来不等于执行了，"逐电机测试"当天下午就总结了，却拖到晚上才真做，中间白绕三轮。
3. **审查按"必须改 / 建议改 / 可以不动"分档** —— 避免把设计选择判成错误，比如"LED 常亮还是常灭"是设计选择不是 bug。
